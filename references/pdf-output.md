# Readable PDF Output

ใช้ไฟล์นี้เมื่อผู้ใช้ขอ PDF, printable plan, one-page field card, เอกสารสรุป หรือไฟล์สำหรับเปิดดูหน้างาน อย่าสร้าง PDF เองเมื่อผู้ใช้ต้องการเพียงคำตอบในแชต

## เลือกโหมดเอกสาร

- **Quick field plan:** 2-3 หน้า เน้น P1, checklist และ workflow สำหรับเปิดดูหน้างาน
- **Readable summary:** 4-6 หน้า ครอบคลุม packaging, story, filming, safety และ editing
- **Full production book:** ใช้เมื่อผู้ใช้ขอรายละเอียดครบหรือมีงานหลายวัน แยกหนึ่งหัวข้อหลักต่อหน้า

ถ้าผู้ใช้ไม่ระบุ ให้ใช้ Readable summary และตั้งชื่อไฟล์จากชื่องาน เช่น `coding-thailand-vlog-plan.pdf` ถามตำแหน่งไฟล์เฉพาะเมื่อไม่สามารถอนุมานจากบริบทได้

## จัดโครงหน้า

ใช้ลำดับนี้เป็นค่าเริ่มต้นและตัดส่วนที่ไม่เกี่ยวข้อง:

1. **Cover + Brief:** ชื่องาน, duration, team, gear, platform และ story question
2. **Packaging + Story:** viewer promise, title options, thumbnail moment และ progressive beats
3. **Field Plan:** P1 timeline ก่อน แล้วค่อยสรุป P2/P3 และ minimum coverage
4. **Safety + Privacy:** emergency fallback, consent และ screen-secret checklist
5. **Editing:** retention map, workflow, export QC และ post-publish note
6. **Field Card:** checklist ตัวใหญ่หนึ่งหน้าสำหรับใช้ระหว่างงาน เมื่อเอกสารยาวหรือผู้ใช้ต้องการ printable plan

## ทำให้อ่านง่าย

- ใช้ฟอนต์ที่รองรับภาษาไทยและฝังฟอนต์ใน PDF เมื่อเครื่องมือรองรับ
- ใช้ body 9.5-11 pt, table 8.5 pt ขึ้นไป, heading 18-28 pt และ leading อย่างน้อย 1.3 เท่าของขนาดตัวอักษร
- ใช้หนึ่งสารหลักต่อหน้าและหนึ่งตารางหลักต่อหน้า ถ้าตารางเกิน 7-8 แถวให้แยกหน้า เปลี่ยนเป็น cards หรือย่อคอลัมน์
- ให้ P1, story question, hook, fallback และ final rule เห็นได้จากการกวาดตา ใช้ callout หรือสี accent แทนการใช้ตัวหนาทั้งหน้า
- ใช้ whitespace เพื่อแบ่งกลุ่ม ห้ามลดฟอนต์เพื่อยัดเนื้อหา และหลีกเลี่ยงหน้าที่โล่งเพราะเนื้อหาหลุดไปหน้าใหม่เพียงไม่กี่บรรทัด
- จำกัด palette หลัก 3-4 สี ให้ contrast สูงและยังอ่านได้เมื่อพิมพ์สีซีด
- ใช้ checkboxes กับรายการหน้างาน และใช้ timeline/cards กับเหตุการณ์ที่เปลี่ยนตามลำดับ
- ใช้ภาษาไทยเป็นหลัก เก็บศัพท์อังกฤษเฉพาะคำที่ทีมตัดต่อหรือโปรแกรมใช้จริง

## ลดความหนาแน่นของข้อมูล

แปลงตารางกว้างเป็นรูปแบบที่อ่านง่ายกว่า:

- แยก `ภาพ/เสียง/หน้าที่/fallback` ออกเป็น P1 cards แทนตาราง 5 คอลัมน์
- แสดง progressive beat เป็น `เป้าหมาย -> สิ่งที่เปลี่ยน -> หลักฐาน`
- รวม P2/P3 เป็นกล่องสรุป ไม่ต้องให้รายละเอียดเท่ากับ P1
- ใช้ field card ซ้ำสาระสำคัญได้ เพราะมีหน้าที่ใช้งานต่างจากหน้าคำอธิบาย
- ตัดคำอธิบายที่ซ้ำกับหัวตารางหรือเห็นได้จาก label

## สร้างและตรวจ PDF

ใช้ความสามารถสร้าง PDF ที่มีในสภาพแวดล้อม เช่น PDF skill หรือเครื่องมือเอกสารที่รองรับภาษาไทย แล้วทำตามลำดับ:

1. สร้างไฟล์ไปยังตำแหน่งที่ผู้ใช้ระบุหรือยืนยันจากบริบท
2. เปิดไฟล์ที่เขียนเสร็จและตรวจจำนวนหน้า metadata และข้อความสำคัญ
3. เรนเดอร์ทุกหน้าเป็น PNG และตรวจหน้าปก ตาราง การตัดหน้า footer และ glyph ภาษาไทย
4. แก้จนไม่มีข้อความล้น ซ้อน ถูกตัด หรือเล็กเกินอ่านจริง
5. ลบไฟล์ builder และภาพ QA ชั่วคราว เหลือ final PDF กับ asset ที่ผู้ใช้ขอ
6. รายงานชื่อไฟล์ จำนวนหน้า และสิ่งที่ตรวจ โดยไม่อ้างว่า QA ผ่านถ้ายังไม่ได้ดูภาพทุกหน้า

## Final QA checklist

- [ ] ชื่อไฟล์และหัวเรื่องตรงกับงาน
- [ ] ตัวอักษรไทยไม่มีสี่เหลี่ยมหรือวรรณยุกต์หาย
- [ ] Body และตารางอ่านได้ที่ zoom 100%
- [ ] ไม่มีแถวตารางหรือหัวข้อค้างเดี่ยวข้ามหน้า
- [ ] P1, emergency และ privacy หาเจอภายในไม่กี่วินาที
- [ ] Header, footer และเลขหน้าสม่ำเสมอ
- [ ] สีและเส้นยังแยกกลุ่มได้เมื่อพิมพ์
- [ ] เปิด PDF รอบสุดท้ายหลังแก้และเรนเดอร์จากไฟล์เดียวกับที่ส่ง
