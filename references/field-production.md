# Field Production Playbook

ใช้ไฟล์นี้เมื่อทำ shot priority, emergency checklist, privacy checklist หรือปรับแผนตามจำนวนคนถ่าย เลือกเฉพาะรายการที่สัมพันธ์กับงานจริง

## Shot priority

จัดทุกช็อตเป็นสามระดับโดยตัดสินจากผลกระทบต่อเรื่อง:

| ระดับ | เกณฑ์ | ตัวอย่าง |
|---|---|---|
| P1 ต้องมี | ถ้าขาดแล้วคนดูไม่รู้เป้าหมาย การเปลี่ยนแปลง หรือผลลัพธ์ | เป้าหมายก่อนเริ่ม, timer, ปัญหาหลัก, หลักฐาน submit, result, reaction |
| P2 ควรมี | ช่วยให้เข้าใจบริบทและตัดต่อได้ลื่นขึ้น | establishing, เดินทาง, wide/medium/close-up, transition, room tone |
| P3 ถ้ามีเวลา | เพิ่มสีสันหรือ production value แต่ไม่เปลี่ยนสาระ | cinematic montage, food shot, gear beauty shot, extra timelapse |

จำกัด P1 ให้สั้นและทำได้จริง ถ้าถ่ายคนเดียว ให้ใช้ P1 ไม่เกิน 8-12 รายการต่อวัน และผูกกับ checkpoint ที่เกิดการเปลี่ยนแปลงแทนการตั้งเตือนถ่ายทุกชั่วโมง

## Minimum viable coverage

ถ้ามีเวลาถ่ายน้อย ให้เก็บอย่างน้อย:

1. ประโยคเป้าหมายก่อนเริ่ม
2. ภาพสถานที่หนึ่ง wide และเสียงบรรยากาศ 10 วินาที
3. screen recording หรือภาพมือทำงานที่เห็น progress
4. error, obstacle หรือการตัดสินใจหนึ่งจุด
5. timer, score, build version หรือหลักฐานสถานะ
6. reaction ทันทีหลัง submit/ประกาศผล
7. closing reflection ว่าเกิดอะไรขึ้นและจะทำอะไรต่อ

## Emergency checklist

สร้าง checklist เฉพาะความเสี่ยงที่เกี่ยวข้องและระบุ fallback หนึ่งบรรทัด:

| ความเสี่ยง | ป้องกันก่อนเริ่ม | Fallback ที่ซื่อสัตย์ |
|---|---|---|
| แบตหมด | ชาร์จเต็ม, power bank, สายสำรอง, airplane mode เมื่อเหมาะสม | ใช้เสียง recap และภาพหลักฐานที่เหลือ |
| พื้นที่เต็ม | เคลียร์พื้นที่, ประเมินนาทีที่ถ่ายได้, ปิดไฟล์ขนาดเกินจำเป็น | ถ่ายเฉพาะ P1 และย้ายไฟล์ช่วงพัก |
| เสียงดัง/ไมค์เสีย | test recording, headphone check, เก็บ room tone | อัด voice-over หลังงานและระบุว่าเป็นการเล่าย้อน |
| ความร้อน/เครื่องค้าง | หลีกเลี่ยงชาร์จพร้อมถ่ายหนัก, ถอดเคสเมื่อปลอดภัย | สลับเครื่องหรือหยุดถ่าย B-roll ที่ไม่จำเป็น |
| อินเทอร์เน็ตล่ม | เตรียม offline notes และบันทึกหน้าจอในเครื่อง | ถ่าย reaction กับผลกระทบ แล้วอธิบายด้วย title card |
| ลืมถ่ายจุดสำคัญ | ผูก P1 กับ milestone และตั้ง reminder ไม่กี่จุด | ใช้หลักฐานจริงหลังเหตุการณ์ ห้ามจัดฉากเป็นเหตุการณ์สด |
| ไฟล์เสีย/หาย | ตรวจไฟล์หลังช่วงสำคัญและสำรองอย่างน้อยหนึ่งชุด | ใช้ไฟล์ proxy, ภาพนิ่ง, log หรือ screen capture ที่ตรวจสอบได้ |

## Privacy และสิทธิ์

ตรวจรายการนี้ก่อนถ่ายและก่อน export:

- ตรวจนโยบายสถานที่ กติกาการแข่งขัน NDA และพื้นที่ห้ามถ่าย
- ขอความยินยอมจากผู้ที่ระบุตัวได้ โดยเฉพาะบทสนทนา close-up และเสียงส่วนตัว
- ซ่อน API key, access token, password, email, เบอร์โทร, QR code, private URL, repository และ notification
- ปิด notification และใช้ demo data เมื่อทำ screen recording
- ตรวจภาพสะท้อน กระดาน whiteboard ป้ายชื่อ badge และจอของทีมอื่น
- เบลอหรือครอปข้อมูลส่วนบุคคลก่อนส่งไฟล์ให้ editor และตรวจซ้ำบน master export
- ใช้เพลง ฟอนต์ ภาพ และฟุตเทจที่มีสิทธิ์เผยแพร่บนแพลตฟอร์มเป้าหมาย
- แยกไฟล์ consent หรือ release จากไฟล์วิดีโอเมื่อโครงการต้องมีหลักฐาน

อย่าตีความการอยู่ในสถานที่สาธารณะว่าเป็นความยินยอมอัตโนมัติ ให้แนะนำผู้ใช้ตรวจข้อกำหนดท้องถิ่นเมื่อมีความเสี่ยงทางกฎหมาย

## แบ่งงานตามขนาดทีม

### ถ่ายคนเดียว

- ใช้กล้องหลักหนึ่งตัวและ preset เดียวให้มากที่สุด
- วางกล้องนิ่งช่วงทำงาน และหยุดเฉพาะ checkpoint ที่เรื่องเปลี่ยน
- ใช้ mini-confessional 15-30 วินาทีแทนการเล่าทุกขั้นตอน
- ให้การแข่งขันมาก่อนการเก็บ P2/P3

### ทีม 2 คน

- ให้คนหนึ่งรับผิดชอบงานแข่งขันและ screen evidence
- ให้อีกคนเก็บ reaction, environment, audio และ continuity
- ตกลงสัญญาณก่อนถ่ายบทสนทนาและเวลาห้ามรบกวน

### ทีม 3 คนขึ้นไป

- แยกบทบาท producer/story, camera/audio และ data wrangler/editor liaison
- ใช้ shot log ร่วมกัน ระบุเวลา ไฟล์ เหตุการณ์ และสิทธิ์การใช้
- ตั้งจุดสำรองไฟล์และผู้รับผิดชอบเพียงคนเดียวเพื่อลดไฟล์ซ้ำหรือสูญหาย

## งานวันเดียวและหลายวัน

- งานวันเดียว: ผูก P1 กับ start, first build, obstacle, pivot, submit และ result
- งานหลายวัน: เปิดแต่ละวันด้วยเป้าหมาย ปิดด้วยสถานะล่าสุด และสำรองไฟล์ก่อนนอน
- งานที่ไม่รู้เวลาจบ: ใช้ milestone แทน hour-counter และเตรียม closing reflection ได้หลายจุด
